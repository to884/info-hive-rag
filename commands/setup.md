description: RAG の派生データの保存先、埋め込みモデル、検索の設定を変える。
argument-hint: "<任意の派生データの保存先や、モデルの指定>"
---

`rag` MCP サーバーの `configure` に、ユーザーが指定した設定だけを渡す。派生データの保存先は `data_dir`、埋め込みモデルは `embedding_model`、検索の設定は `retrieval` に渡す。指定のない項目は今の設定のまま残る。

PDF のフォルダは登録しない。PDF は `/wiki:ingest` で取り込むときに、絶対パスで渡す。どこにある PDF でもよい。rag 0.3.0 の参照ルート（`reference_roots`）は使わなくなった。設定ファイルに残っていれば、`configure` で保存し直したときに消える。

埋め込みモデルの暫定既定値は `cl-nagoya/ruri-v3-130m`。CPU が非力な環境では、ユーザーの希望に応じて `30m` または `70m` を指定できる。既存の索引がある場合、モデルの変更には全資料の再投入が必要だと説明する。

PDF の原本には書き込まない。派生データの保存先の既定値は OS の利用者用アプリケーションデータ領域である。派生データの保存先の中にある PDF は登録できない。OneDrive などの同期対象のフォルダを指定する場合は、再生成できるデータの同期に時間がかかることを説明する。

PDF の取り込みは `/wiki:ingest` で行う。取り込みを起点に抽出、OCR、埋め込み、索引更新が実行される。初回は実行環境とモデルを取得する。検索と埋め込みはローカルで処理するが、回答に使う上位チャンクは Claude Code に渡る。
