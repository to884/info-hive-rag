# info-hive-rag

RAG（Retrieval-Augmented Generation、検索拡張生成）を扱う、info-hive の Claude Code プラグインです。

プラグイン [wiki@info-hive](https://github.com/to884/info-hive-wiki) に依存します。`wiki` を有効にした状態で使います。

PDF の抽出、必要な OCR、埋め込み、ローカルのハイブリッド検索を提供します。
PDF の取り込みは永続ジョブとして進め、Claude Code を終了した後は次の rag の MCP 接続時に再開します。

## 名前

| 対象 | 名前 |
| --- | --- |
| リポジトリ | `to884/info-hive-rag` |
| プラグイン | `rag` |
| マーケットプレイス | `info-hive` |
| 導入するときの名前 | `rag@info-hive` |

## 導入

Claude Code で、マーケットプレイスを追加してから `rag` を入れます。依存先の `wiki` も自動で導入されます。

```text
/plugin marketplace add to884/info-hive-marketplace
/plugin install rag@info-hive
```

リポジトリは非公開のため、GitHub の認証情報が必要です。

## PDF の取り込み

1. `/rag:setup` で PDF のあるフォルダを参照ルートとして登録します。派生データは原本と別の場所に保存します。
2. `/wiki:ingest <PDF のパス>` を実行します。wiki が `register_pdf` を呼び、ジョブ ID を受け取ります。自然言語で PDF の取り込みを依頼した場合も同じ手順を使います。
3. `/rag:status` で進捗を確認します。`completed` になると、wiki が抽出済みの Markdown を読み、ソースの要約ページを作成できます。

`queued`、`running`、`paused` は処理中です。PDF の索引化が完了したことや、wiki の要約ページが完成したことを意味しません。
PDF の原本はコピーしません。要約ページの `raw` は `books:日本語資料.pdf` のような名前付き参照になります。

Claude Code の終了時は、ワーカーと OCR の子プロセスを停止します。次回 rag の MCP 接続時に未完了のジョブを再開します。
保存済みのページと埋め込みバッチを再利用し、索引が揃ってから検索対象として公開します。
同じ PDF の OCR ページでは、モデルを読み込んだ子プロセスを再利用します。
文字が得られなかったページも処理結果を保存して次へ進み、PDF 全体で検索可能な本文が得られない場合はジョブを失敗として記録します。
キャンセル済みと失敗したジョブは自動再試行しません。

埋め込みはモデル本来の文脈長（現在の Ruri v3 は最大 8,192 トークン）まで扱い、上限超過はエラーにします。
本文を無言で切り捨てません。長い入力ではメモリを抑えるため埋め込みのバッチ数を自動で下げます。
この入力方針の更新により、以前の試作索引は別の `data_dir` で再構築してください。

| MCP ツール | 用途 |
| --- | --- |
| `configure` | 参照ルート、派生データの保存先、モデルを設定する。未完了ジョブがある間は変更しない |
| `register_pdf` | PDF を登録し、ジョブ ID を返す。受付時に PDF 全体は読み込まない |
| `ingest_pdf` | 同じ引数を受け付ける `register_pdf` の別名。同期的な完了待ちではない |
| `job_status` | 指定した wiki とジョブの進捗・結果を返す。`wait_seconds=1〜30` で短時間待機できる |
| `cancel_job` | キャンセルする。索引の公開開始後は受理しないため、`cancellation_accepted` を確認する |
| `retry_job` | 失敗またはキャンセルしたジョブを明示的に再試行する |
| `status` | 対象 wiki の索引件数とジョブ一覧を返す |
| `search` | 公開済みの索引から本文、出典、ページ番号を検索する |

同じ保存先を使う複数の接続では、索引化を進めるワーカーを一つにします。OS の常駐サービスは作りません。
初回は `uv` が依存関係を取得し、OCR と埋め込みを初めて使う際にモデルを取得します。
検索も同じワーカーに渡すため、MCP の受付は検索用ライブラリやモデルの読み込みを待ちません。モデルの重みは検索・索引化時に読み込みます。
索引化と検索はワーカー内で直列に進めます。長い索引化の途中の検索は待機するため、完了後に検索してください。

## PC ごとの設定

設定ファイルは OS のアプリケーションデータ領域に置き、`INFO_HIVE_RAG_CONFIG` で場所を変更できます。
高度な設定では `model_cache_dir` と `uv_cache_dir` を指定し、準備済みのモデルと実行環境を再利用できます。
`uv_cache_dir` は OCR の実行環境に使います。MCP サーバー自身の実行環境キャッシュは、Claude Code の起動前に環境変数 `UV_CACHE_DIR` で指定できます。
設定変更はその MCP 接続に反映します。別の接続にも反映する場合は再接続してください。

### リランクと ANN の検索設定

`configure` の `retrieval`、または設定ファイルで次の値を指定できます。

| キー | 既定値・用途 |
| --- | --- |
| `reranker` | `off`。`xsmall-int8` または `tiny-int8` で CPU の ONNX リランカーを有効にする |
| `rerank_limit` | `8`。順位融合の上位何件をリランクするか（1〜50） |
| `min_rerank_score` | 未指定。指定時は閾値以上のリランク済み候補だけを返す |
| `search_nprobes` | `20`。作成済み ANN 索引の探索パーティション数 |
| `search_refine_factor` | `4`。作成済み ANN 索引の再評価候補の倍率 |

リランクは質問と本文の組を最大512トークンに切り詰めて評価します。
`search` の `rerank_score` はリランカーの生のスコアで、回答の正しさの確率ではありません。
`score` は従来の順位融合の値であり、リランク後の並び順は返された配列を使います。
閾値は利用資料と質問で検証してから設定してください。候補が残らない場合は `abstained: true` と空の結果を返します。
これらの設定は埋め込みの作り直しを必要としません。
`configure` で `embedding_model` を省略すると、現在のモデルを維持します。

### 索引の自動作成と更新

PDF の取り込みに合わせて全文・世代索引を作成し、チャンクが既定の 256 行に達すると IVF_SQ の ANN 索引を作成します。
追加や差し替えを取り込み時に反映し、行数や削除数が再構築の基準に達すると ANN 索引を作り直します。
再接続時は保存済みの索引状態を照合して中断した処理を再開します。索引の状態は MCP の `status` で確認できます。

設定ファイルでは `ann_min_rows`（既定 256）、`ann_rebuild_growth`（既定 4 倍）、`index_cleanup_age_days`（既定 7 日）を指定できます。
